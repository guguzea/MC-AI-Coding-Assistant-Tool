# 版本变更记录：1.19.x

> 本档规则树只适用于 **Forge 1.13.2**。本章记录 **Minecraft 1.19.x** 的变更，用途有两个：
> 1. 判断「把本档工程往 1.19.x 搬会断什么」；
> 2. 防止把 1.19+ 的写法当 1.13.2 教程写进当前工程。
>
> 移植问题先读本档 `knowledge/porting/`（`00-porting-guide.md` / `01-api-cross-loader.md` / `02-version-migration.md` / `03-real-world-examples.md`），再走 `analyze_porting_path` / `get_migration_guide`；**不要**打开邻档 `.cursor/rules` 当加载器 Read。

## 1.19.4 Forge（45.x）重要变更

### 注册：DeferredRegister 已是官方文档主推

Forge 1.19.4 官方文档（`search_forge_docs --version=1.19.4` → `1.19.4/concepts_registries`）给出的注册写法：

```java
// Forge 1.19.4 文档主写法
private static final DeferredRegister<Block> BLOCKS =
    DeferredRegister.create(ForgeRegistries.BLOCKS, MODID);

public static final RegistryObject<Block> ROCK_BLOCK =
    BLOCKS.register("rock", () -> new Block(BlockBehaviour.Properties.of(Material.STONE)));

public ExampleMod() {
    BLOCKS.register(FMLJavaModLoadingContext.get().getModEventBus());
}
```

同页还给出 mod bus 上的备选事件（注意：`RegisterEvent` 收的是 `ForgeRegistries.Keys.*` + helper lambda，**不是** 三参数 `event.register(registry, name, supplier)`）：

```java
@SubscribeEvent
public void register(RegisterEvent event) {
    event.register(ForgeRegistries.Keys.BLOCKS, helper -> {
        helper.register(new ResourceLocation(MODID, "example_block_1"), new Block(/* ... */));
    });
}
```

> ⚠️ `forge/1.20.1/knowledge/version-changes/1.19.x.md` 里把「旧方式」写成 `RegisterEvent<Block>` + `event.register(ForgeRegistries.BLOCKS, "my_block", MyBlock::new)`，与该版官方文档的形态不一致，**不要照抄那一段**。

### 1.19.x 相对 1.18.x 的关键变化

| 项目 | 1.18.x | 1.19.x | 依据 |
|------|--------|--------|------|
| Forge | 40.x | 45.x（1.19.4） | 本仓 porting 对照表 + `forge/1.19.4/knowledge/version-changes/1.19.x.md`（`forge_version=45.4.0`）；1.20.1 档同章写 `44.1.0` 与其标题「45.x」矛盾，除 45.x 之外的构建号一律 **未核实** |
| ForgeGradle | **5.x** | **5.x 或 6.x**（1.19.2+ 走 6.x） | `forge/1.18.2/knowledge/version-changes/1.19.x.md` |
| Gradle | 7.x | 8.x + FG 6.x | `forge/1.19.4/AGENTS.md` 基本信息表 |
| Java | 17 | 17 | `forge/1.19.4/AGENTS.md` |
| 流体 | `FluidAttributes` | 新增 `FluidType`（独立注册表） | 见下节 |
| pack_format | 本档记法不一致（8 / 9），**未核实** | 1.19.4 = 数据包 **12** / 资源包 **13** | `forge/1.19.4/knowledge/version-changes/1.19.x.md` pack_format 表 |

### 流体：FluidType（1.19+）

1.16.5 / 1.17.1 档的差异表都记着「本档无 `FluidType`，只有 `FluidAttributes`」，而 1.19.4 档的 `mc-fluid` Skill 已把 `FluidType` 列为**必注册的独立注册表**：

```java
// 1.19+ 形态（来源：forge/1.19.4 mc-fluid Skill；Forge 构建号未核实）
public static final DeferredRegister<FluidType> FLUID_TYPES =
    DeferredRegister.create(ForgeRegistries.Keys.FLUID_TYPES, MOD_ID);

public static final RegistryObject<FluidType> MY_FLUID_TYPE = FLUID_TYPES.register("my_fluid",
    () -> new FluidType(FluidType.Properties.create() /* TODO(未核实): 其余属性方法名 */));
```

> `FluidType` / `ForgeRegistries.Keys.FLUID_TYPES` / `FluidType.Properties.create()` 三处名字来自 1.19.4 档内已核实 Skill；引入 `FluidType` 的**确切 Forge 版本号**未核实，不要往工程里写构建号。

### MobCategory 仍是 MobCategory

`MobCategory` 在 1.19.x / 1.20.x 都是 Forge / mojmap 名。`SpawnGroup` 是 **Yarn（Fabric）** 名，不是 Forge 的重命名，别从 Fabric 教程抄进 Java 工程。

### Mixin / DataGen

- Mixin 7.x 在 1.19.x 可用，插件配置与 1.20.x 一致。
- `RecipeProvider` / `LootTableProvider` 的 DataGen API 在 1.19.x 与 1.20.x 基本一致（`forge/1.19.4/knowledge/version-changes/1.19.x.md` 迁移注意事项）。
- 实体：`EntityType.Builder` 在 1.18.2 与 1.20.1 索引中都含 `of` / `sized` / `immuneTo` / `build`（`query_api --class='EntityType$Builder'`）→ 1.18→1.20 这条线**没有**断点。

## 对本档（forge/1.13.2）工程的影响

### A. 仍留在 1.13.2 时：禁止写进工程的东西

下列 1.19+（乃至 1.15+/1.17+）写法在 **1.13.2 不存在**，出现即编译失败或运行期炸：

| 不要写 | 1.13.2 正确写法 |
|--------|-----------------|
| `DeferredRegister` / `RegistryObject` | `@EventBusSubscriber` + `RegistryEvent.Register<T>` + `event.getRegistry().register(...)`（本档 AGENTS 明示 1.13.2 无 DeferredRegister） |
| `BlockBehaviour.Properties.of(...)` | `Block.Properties.create(Material)` |
| `.strength(...)` / `.destroyTime(...)` | `.hardnessAndResistance(...)` |
| `BlockEntity` / `EntityType.Builder.of()` | `TileEntity` / `createNewTileEntity()`（本档 `1.13.x.md` 只核实到 TileEntity 一侧；实体注册写法以本档 `01-registry.mdc` 为准） |
| `CompoundTag` | `NBTTagCompound` |
| `MenuType` / `AbstractContainerMenu` / `MenuProvider` | `ContainerType` / `Container` / `IGuiHandler` |
| `CreativeModeTab` | `ItemGroup` |
| `world.isClientSide` | `world.isRemote` |
| `FluidType` | `FluidAttributes`（本档是否已有 `FluidAttributes` **未核实**，改流体前查本档规则） |
| `ForgeRegistries.Keys.*` | `ForgeRegistries.*`（1.19.4 才见到 Keys 形态） |

`mapping_channel=mcp` + `mapping_version=1.13.2`（MCP SRG）；Java 8；Gradle 4.9 + FG 3.+ —— 全都在本档 `AGENTS.md` / `1.13.x.md` 已核实（官方 1.13.2-25.0.223 MDK：`build.gradle:19` = `'1.8'`，`gradle-wrapper.properties:5` = `gradle-4.9-bin.zip`），别被 1.19+ 的 `official`/`parchment` + Java 17 + Gradle 8 覆盖掉。

### B. 真要把本工程升到 1.19.x：按顺序处理的断裂点

1.13.2 → 1.19.x 是**跨大版本**，不是改 `gradle.properties`：

1. Java 8 → Java 17；FG 3.+ → FG 6.x（Gradle 4.9 → 8.x）。
2. Mappings：MCP SRG（1.13.2）→ official / Parchment（1.19.4 档用 `1.19.4-2023.06.26`）。整批方法名跟着换。
3. 注册形态：`RegistryEvent.Register<T>` + `setRegistryName(new ResourceLocation(...))` → `DeferredRegister.create(ForgeRegistries.X, MOD_ID)` + `RegistryObject`，并在 mod bus 上 `register(bus)`。
4. 类名批量重命名（本档 `1.13.x.md` 的对照表 + 1.17+ 生效）：`Block.Properties` → `BlockBehaviour.Properties`、`TileEntity` → `BlockEntity`、`ITileEntityProvider` → `EntityBlock`、`NBTTagCompound` → `CompoundTag`、`Container`/`ContainerType` → `AbstractContainerMenu`/`MenuType`、`ItemGroup` → `CreativeModeTab`、`world.isRemote` → `world.isClientSide`。
5. 流体若涉及：补 `FluidType` 独立注册（1.19+）。
6. 世界生成 / 高度：1.18.2 起 Y 范围改为 **-64 ~ 320**（`forge/1.18.2/AGENTS.md`），落在 1.13.2 → 1.19.x 路径上，必须一并检查 Y 常量。

> 建议分段：1.13.2 → 1.16.5 → 1.18.2 → 1.19.4，每段单独可编译可跑；一口气跳到 1.19.x 会让第 2、4 步的重命名与第 3 步的注册改造互相掩盖故障。

### C. 工具边界

`query_api` 的索引覆盖约 **1.16.5–1.20.4**：查 1.13.2 类名会 `found:false`，查本章 1.19.x 结论请用 `--version=1.19.4`。1.13.2 教程一律走 `search_forge_docs --version=1.13.2`，不要用 `query_api` 核 1.13.2 的 `Block` 构造。
