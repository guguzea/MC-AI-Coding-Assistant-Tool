# 版本变更记录：1.21.x

> 本档规则树只适用于 **Forge 1.18.2**。本章记录 **Minecraft 1.21.x**。
>
> ⚠️ **本仓没有 Forge 1.21.x 文档语料**：`list_forge_versions` 最新为 **1.20.4**（notes 明示 `forge/1.21.1` 是 draft：无 00–10 规则树、不在文档清单）。1.21.x 的 API 事实**全部属 NeoForge 侧**，本章逐条标注来源；查文档用 `search_neoforge_docs`（`list_neoforge_versions` 含 `1.21.1 / 1.21.3 / 1.21.5 / 1.21.8 / 1.21.10 / 1.21.11 / 26.1`）。

## 先换平台，再换版本

来源：本仓 `knowledge/porting/02-version-migration.md`（1.20.1 → 1.20.2 分叉段，1.17.1 / 1.16.5 两档同文）+ `neoforge/*/AGENTS.md`：

- Forge 自 1.20.2 起不是主线，本仓版本对照表把 1.21.x 的加载器记为 **NeoForge 21.x**。
- `net.minecraftforge.*` → `net.neoforged.*`（全局替换）。
- `META-INF/mods.toml` → `neoforge.mods.toml`。
- `RegistryObject<T>` → `DeferredHolder<T, T>`（本档 1.18.2 用的是 `RegistryObject`）。
- 构建插件：ForgeGradle → NeoGradle / ModDevGradle，移除 `fg.deobf`（**具体插件版本号未核实**，以 `download_official_mdk` 拉的该档 MDK 为准）。
- Java：17 → **21**（`neoforge/1.21.11/AGENTS.md`；porting 对照表亦记 26.1 之前的版本用 Java 21）。

## 注册（NeoForge 1.21.1）

来源：`neoforge/1.21.1/.cursor/rules/01-registry.mdc`（注明取自 `docs.neoforged.net/docs/1.21.1/concepts/registries/`）：

```java
public static final DeferredRegister.Blocks BLOCKS =
    DeferredRegister.createBlocks(ExampleMod.MODID);
public static final DeferredRegister.Items ITEMS =
    DeferredRegister.createItems(ExampleMod.MODID);

// 持有类型是 DeferredBlock / DeferredItem / DeferredHolder，不要照 Forge 1.18.2 假定 RegistryObject
```

- 备选事件仍是 **`RegisterEvent`（mod bus，构造之后）**；运行时查询走 vanilla `Registry`，`DeferredRegister` 不是运行时 map。
- 自定义 datapack registry：`ResourceKey.createRegistryKey(ResourceLocation.fromNamespaceAndPath("yourmodid", "spells"))` 一类写法。

## ResourceLocation：构造器私有（NeoForge 1.21 primer 实证）

`get_neoforge_doc_full --id=primer/1.21 --version=1.21.1`（`get_neoforge_doc_full` **必须带 `--version`**）：

| 1.18.2 可用 | 1.21 替代 |
|-------------|-----------|
| `new ResourceLocation(String, String)` | `ResourceLocation.fromNamespaceAndPath(String, String)` |
| `new ResourceLocation(String)` | `ResourceLocation.parse(String)` |
| `new ResourceLocation("minecraft", String)` | `ResourceLocation.withDefaultNamespace(String)` |
| `ResourceLocation.of` | `ResourceLocation.bySeparator` |
| `ResourceLocation.isValidResourceLocation` | 已移除 |

## 数据组件（Data Components）

同一 primer 页确实出现：`net.minecraft.core.component.DataComponentMap`（`makeCodec` / `makeCodecFromMap`）、`DataComponentPatch`、`net.minecraft.core.component.TypedDataComponent#createUnchecked`、`net.minecraft.commands.arguments.item.ItemInput` 改收 `DataComponentPatch`。

- 对本档的意义：1.18.2 里往 `CompoundTag` 上直接读写自定义数据的代码，在 1.21 对应的是**数据组件**，不是同名 API；不要指望 `CompoundTag` 那套机械平移。
- NeoForge 侧对象上的自定义数据由 **`AttachmentType`** 承担（来源：`neoforge/1.21.1` 档 `mc-capability` Skill 名册；细节未展开核实，动代码前 `search_neoforge_docs`）。

## 网络（NeoForge 1.21）

来源：`get_neoforge_doc_full --id=networking/payload --version=1.21.1`，页内含 `CustomPacketPayload`、`PayloadRegistrar`、`RegisterPayloadHandlersEvent`、`StreamCodec`、`IPayloadContext`。

| 本档 1.18.2（Forge） | NeoForge 1.21 |
|----------------------|---------------|
| `SimpleChannel` + 手写 encode/decode/consumer | `CustomPacketPayload` + `StreamCodec` |
| `NetworkRegistry.newSimpleChannel(...)` + `INSTANCE.registerMessage(id, Class, encoder, decoder, consumer)`（本档 `06-networking.mdc` 实证形态） | `RegisterPayloadHandlersEvent` + `PayloadRegistrar`（**复数**） |
| `PacketDistributor` 发送 | handler 收 `IPayloadContext` |

> NeoForge 1.20.4 是**单数**形态 `RegisterPayloadHandlerEvent` + `IPayloadRegistrar`（`neoforge/1.20.4/AGENTS.md`）。1.20.4 与 1.21 的 payload 名字不要互抄。
> MCP `generate_network_packet` 在 1.21 侧选 `neoforge_1.21` 平台。

## 其他 1.21 断点（primer 页实证）

- `net.minecraft.world.item.CreativeModeTab#getBackgroundSuffix` → `getBackgroundTexture`；创造标签页注册 API 与 1.20.1 不同。
- `net.minecraft.data.loot.BlockLootSubProvider` 改收 `HolderLookup$Provider`，常量 `HAS_SILK_TOUCH` → 方法 `hasSilkTouch`。
- 映射：官方 Mojang 名为默认；`convert_mapping` 在 26.1+ 会拒 yarn（1.21.x 仍混淆，别把两档混为一谈）。

## 对本档（forge/1.18.2）工程的影响

### A. 仍留在 1.18.2 时不要写

`fromNamespaceAndPath` / `parse` / `withDefaultNamespace` / `bySeparator`（本档 `new ResourceLocation(...)` 完全正常）、`DeferredHolder` / `createBlocks` / `createItems`、`DataComponentPatch` / `DataComponentMap`、`PayloadRegistrar` / `CustomPacketPayload` / `StreamCodec`、`neoforge.mods.toml`、`net.neoforged.*`、Java 21 toolchain。写了就是给一个 Forge 工程套 NeoForge 的骨架，编译期就炸。

### B. 1.18.2 → 1.21.x 的账（比 1.13.2 起步短，但含换平台）

1. **1.19 一步**：`FluidType` 独立注册表；`RegistryEvent.Register<T>` → `RegisterEvent` + `ForgeRegistries.Keys.*` helper 形态；FG → 6.x、Gradle → 8.x、`pack_format` → 15。
2. **1.20 一步**：`BlockBehaviour.Properties.of(Material.X)` → 无参 `of()`（见同目录 `1.20.x.md`，这是本档出发**唯一**的硬 API 断裂）。
3. **平台一步**：Forge → NeoForge —— 包名、`neoforge.mods.toml`、`RegistryObject`→`DeferredHolder`、构建插件、Java 17→21。
4. **1.21 一步**：`ResourceLocation` 构造方式、数据组件、payload 网络、`BlockLootSubProvider` / `CreativeModeTab` 细节。

分段执行、每段单独可编译；第 3 步和第 4 步混在一起做时，NeoForge 的名字最容易被按 Forge 记忆补错。分析走 `analyze_porting_path`，脚手架走 `port_project`（默认 dryRun，写盘须用户确认）。

### C. 工具边界

- `query_api` 索引约 **1.16.5–1.20.4**，**不含 1.21.x**；用它查 1.21 类名必然 `found:false`，那不代表游戏里没有这个类。
- 1.21.x 只能 `search_neoforge_docs` / `get_neoforge_doc_full --version=<精确版本>`；`search_forge_docs` 没有 1.21.x 版可查。
- 本档 `AGENTS.md` 只覆盖 Forge 1.18.2；升 1.21.x 后**必须**换到 `neoforge/<精确版本>/` 规则树，禁止用本档 00–10 顶。
