# 版本变更记录：1.20.x

> 本档规则树只适用于 **Forge 1.18.2**。本章记录 **Minecraft 1.20.x（Forge 47.x / 48.x）** 的变更：
> 一是给「本档工程往 1.20.x 搬会断什么」列清单，二是划清「留在 1.18.2 时不能写 1.20 的什么」。
> 1.18.2 → 1.20.x 中间的 1.19.x 一步见同目录 `1.19.x.md`。

## 1.18.2 → 1.20.1：只变了这些

### 唯一真正的 API 断裂：Properties 工厂不再带 Material

逐版比对 `query_api --class='BlockBehaviour$Properties'` 的 `of` 重载：

| 版本 | `of` 重载（实测 descriptor） |
|------|------------------------------|
| **1.18.2** | **4 个，全部以 `Material` 开头**：`of(Material)`、`of(Material, Function)`、`of(Material, DyeColor)`、`of(Material, MaterialColor)`。**索引里没有无参 `of()`** |
| 1.19.4 | 4 个，仍以 `Material` 开头（该版官方文档示例 `BlockBehaviour.Properties.of(Material.STONE)`） |
| **1.20.1 / 1.20.4** | **只剩 1 个无参 `of()`**，descriptor = `()L…BlockBehaviour$Properties;` |

```java
// ✅ 本档 1.18.2（无参 of() 在 1.18.2 索引中不存在，别提前写）
BlockBehaviour.Properties.of(Material.WOOD)
    .mapColor(MapColor.WOOD)
    .strength(2.0f)
    .noOcclusion();

// ✅ 1.20.x
BlockBehaviour.Properties.of()
    .mapColor(MapColor.WOOD)
    .strength(2.0f)
    .noOcclusion();
```

> 未核实：1.20.1 里 `net.minecraft.world.level.material.Material` 类是否仍保留（简名 `Material` 在 1.20.1 索引只命中客户端 `net.minecraft.client.resources.model.Material`）。本章只断言「带 `Material` 的 `Properties` 工厂在 1.20.1 索引中已不存在」。

### 没有断的部分

| 项目 | 1.18.2 | 1.20.1 | 依据 |
|------|--------|--------|------|
| 注册 | `DeferredRegister.create(ForgeRegistries.BLOCKS, MOD_ID)` + `RegistryObject` + `BLOCKS.register(modEventBus)` | 一致 | 1.19.4 官方文档 `concepts_registries` 实证同一形态 |
| mod bus 备选事件 | `RegistryEvent.Register<T>` | `RegisterEvent` + `ForgeRegistries.Keys.BLOCKS` + helper lambda | `1.19.4/concepts_registries`；1.18.2 侧形态 **未核实**，以本档 `01-registry.mdc` 为准 |
| 实体 | `EntityType.Builder.of()` | 一致 | `query_api --class='EntityType$Builder'` 在 1.18.2 / 1.20.1 均含 `of` / `sized` / `immuneTo` / `build` |
| Java | 17 | 17 | 本档 `AGENTS.md` |
| DataGen | `RecipeProvider` / `LootTableProvider` | 基本一致 | `forge/1.20.1/knowledge/version-changes/1.19.x.md` |
| Mixin | 7.x 可用 | 7.x 可用，插件配置一致 | 同上 |

### 构建链与元数据要动的地方

来自本档 `knowledge/porting/02-version-migration.md`（1.18.x → 1.20.x 段）：

1. `ForgeGradle 5.x → 6.x`（1.19.2+ 起走 6.x，1.20.x **只有 6.x**）。
2. `Gradle 7.x → 8.x`。
3. `pack_format`：**1.18.2 起数据包与资源包编号分家**，官方 1.18.2-40.3.0 MDK `src/main/resources/pack.mcmeta` 同时给出 `forge:resource_pack_format: 8` 与 `forge:data_pack_format: 9`（外层 `pack_format: 9`），1.20 – 1.20.1 = **15**（1.20.1-47.4.10 MDK）。本档此前「AGENTS 表写 8、porting 表写 9」的冲突因此消解：8 是资源包号、9 是数据包号，两个都对，但必须写明是哪一类包。sha256 见 `mcp-server/data/mdk-checksums.json`。
4. 世界高度：1.18.2 已是 **-64 ~ 320**，1.20.x 不变（本档 `AGENTS.md`）。
5. Mappings：本档 `AGENTS.md` 记 Parchment `1.18.2-2022.08.02`；1.20.1 档记 `official 20231030.163645` 或 `parchment 2023.09.03-1.20.1`，插件 `id 'org.parchmentmc.librarian.forgegradle' version '1.+'`。换版必须换 mapping 版本串，参数名会漂移。
6. Forge 40.x → 47.x（官方 MDK：1.18.2-40.3.0 → 1.20.1-47.4.10；本包 scaffold 钉 `40.1.80`，本档 `knowledge/porting/02-version-migration.md` 版本对照表已记 40.x / 47.x）。

```properties
# 1.20.1 目标形态（数字照抄自 forge/1.20.1/knowledge/version-changes/1.20.x.md）
minecraft_version=1.20.1
forge_version=47.4.18
forge_version_range=[47,)
loader_version_range=[47,)
mapping_channel=official
mapping_version=20231030.163645
```

### 流体：跨 1.19 才会遇到的新增注册表

`FluidType` 是 1.19+ 引入的独立注册表（1.16.5 / 1.17.1 档差异表都记着「本档无 `FluidType`」；1.19.4 档 `mc-fluid` Skill 用 `DeferredRegister<FluidType>` + `ForgeRegistries.Keys.FLUID_TYPES` + `FluidType.Properties.create()`；1.20.1 档 `AGENTS.md` 记「1.20.1 有 `FluidType`」）。本档 1.18.2 仍是 `FluidAttributes` 一侧。引入 `FluidType` 的确切 Forge 构建号 **未核实**。

### 1.20.1 已知坑：ArmorMaterial 与 DeferredRegister

`forge/1.20.1/knowledge/version-changes/1.20.x.md` 记：该问题 1.20.6 才修复（稿内引用 issue **#9961**，标题本身未核实）。1.20.1 上请先把 `ArmorMaterial` 定义完整，再在 `register` 的 lambda 里引用它构造 `ArmorItem`。

### 1.20.2 是分叉点

本仓 porting 笔记：Forge 1.20.2 之后不再更新，社区分叉为 NeoForge（`net.minecraftforge` → `net.neoforged`、`modId="forge"` → `modId="neoforge"`、`RegistryObject<T>` → `DeferredHolder<T, T>`、NeoGradle 7 且移除 `fg.deobf`）。**目标是 1.20.2+ 时先重新判平台**，别按本章继续；详见同目录 `1.21.x.md`。

## 对本档（forge/1.18.2）工程的影响

### A. 仍留在 1.18.2 时不要写

- **无参 `BlockBehaviour.Properties.of()`**（1.18.2 索引里没有；写不带 Material 的 `of()` 会「找不到合适的方法」）。
- `ForgeRegistries.Keys.*` 形态的注册键（本章只核实它在 1.19.4 文档中存在；本档是否已有 **未核实**，查本档 `01-registry.mdc`）。
- `FluidType` / `FluidType.Properties.create()`（1.19+ 才引入）。
- NeoForge 的 `DeferredHolder` / `net.neoforged.*` / `neoforge.mods.toml`（本档是 Forge，`RegistryObject` + `net.minecraftforge.*` + `mods.toml` 才是对的）。
- FG6 的 `plugins { id 'net.minecraftforge.gradle' version '[6.0,6.2)' }`：本档 AGENTS 记 Gradle 7.x + FG 5.x，不要混。

### B. 要升到 1.20.x 的执行顺序

1. `Properties.of(Material.X)` → `Properties.of()` 全量替换（**唯一硬 API 断裂**）。
2. 若跨 1.19：流体补 `FluidType` 注册；`RegistryEvent.Register` → `RegisterEvent` + Keys 形态（如仍在用事件写法）。
3. `build.gradle` FG/Gradle 升级 + `gradle.properties` 版本串 + mapping 版本串。
4. `pack.mcmeta` 的 `pack_format` → 15。
5. 编译通过后再处理上文「1.20.1 已知坑：ArmorMaterial 与 DeferredRegister」。
6. 若目标是 1.20.2 以上：停，改判 NeoForge，走 `1.21.x.md`。

### C. 工具边界

`query_api` 覆盖约 1.16.5–1.20.4，本章所有对照都能用 `--version=1.18.2` 与 `--version=1.20.1` 复跑；本仓 **无** Forge 1.21.x 语料（`list_forge_versions` 最新 1.20.4）。
