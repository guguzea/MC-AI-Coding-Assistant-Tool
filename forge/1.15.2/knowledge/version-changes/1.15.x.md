# 版本变更记录：1.15.x

## 1.15.2 Forge 概述

> 破坏性变更**几乎全部集中在渲染与模型加载**。官方 1.14→1.15 Update Primer 对非渲染部分的原话是「Honestly not much. Ask in the usual channels.」（`1.15.2/primer_1_15`）。其余多是文档口径收紧与原版数据格式调整。

`get_migration_guide` **没有** `1.14.4->1.15.2` 路线（已入库路线最早为 `1.20.1->1.20.4`）；本档查证走 `search_forge_docs --version=1.15.2` + `get_forge_doc_full --id=1.15.2/primer_1_15`。

## 核心变更（1.14.4 → 1.15.2）

### 渲染：批处理（Batching）改造

| 1.14.4 写法 | 1.15.2 写法 |
|-------------|-------------|
| `GlStateManager` / `GL11` 直接调 GL | `RenderSystem`；有 `MatrixStack` + `IRenderTypeBuffer` 时**禁止**直调 GL |
| `Tessellator` 自己 `draw()` | 写入 `IRenderTypeBuffer`，游戏在帧末按 `RenderType` 分层统一 draw |
| 渲染方法无形参约定 | 方法新增 `MatrixStack` 与 `IRenderTypeBuffer` / `IVertexBuilder` |
| 方块渲染类型（solid/cutout/translucent）靠覆写方法 | 改为注册：`RenderTypeLookup.setRenderLayer`，在 `FMLClientSetupEvent` 里调用 |
| 颜色放在隐式全局 GL state（`GlStateManager.color`） | 颜色进顶点数据：`VertexFormat` 加 color 属性，逐顶点传色 |
| `GlStateManager.rotate(90, 0, 1, 0)` | `ms.multiply(Vector3f.POSITIVE_Y.getDegreesQuaternion(90))` |

```java
// ✅ 1.15.2 批处理渲染骨架（名称全部出自 primer_1_15）
RenderType type = RenderType.getEntityTranslucent(location); // 也可查 RenderType / RenderTypeLookup / Atlases
IVertexBuilder vb = buffer.getBuffer(type);
vb.vertex(matrixStack.peek().getModel(), x, y, z).color(r, g, b, a).endVertex();
// ✅ 非批处理环境（如 GUI）里调批处理代码：
IRenderTypeBuffer.Impl buf = IRenderTypeBuffer.immediate(Tessellator.getInstance().getBuffer());
buf.draw();                                // 批处理调用之后
// RenderTypeLookup.setRenderLayer(...)
// TODO(未核实): setRenderLayer 的参数签名 1.15.2 文档未列出，禁止凭记忆填写
```

方法签名里新出现的两个 `int` 是**光照纹理坐标（lightmap）**与**覆盖层纹理坐标（overlay）**。未识别的渲染层共用 fallback buffer，这是实现细节，不要依赖。

### 模型：Forge Blockstate JSON 被移除

- Forge 专用 blockstate JSON（带模型逻辑）**整类取消**——文档称其为「massive hack」。
- 改为扩展**原版** model JSON：新增与 `"model"` 同级的 `"loader"` 字段，可在代码里注册自定义 loader。
- Forge 自带 `.obj` 支持（`1.15.2/models_files`）：OBJ 位置**带** `.obj` 后缀，普通 JSON 模型位置不带 `.json`。
- `.mtl` 与 `.obj` 同名同目录自动使用，其纹理路径多半要手改；`"flip-v": true` 修 V 轴翻转；`textures` 里 `texture0` 可被 `.mtl` 以 `#texture0` 引用。

```json
{ "loader": "forge:obj", "flip-v": true, "model": "examplemod:models/block/model.obj",
  "textures": { "texture0": "minecraft:block/dirt", "particle": "minecraft:block/dirt" } }
```

### 注册（本档文档口径）

1.15.2 文档明确**两种正规方式**：`DeferredRegister` 与 `RegistryEvent$Register`。

```java
// ✅ 方式一：DeferredRegister（挂在 mod 总线）
private static final DeferredRegister<Block> BLOCKS = DeferredRegister.create(ForgeRegistries.BLOCKS, MODID);
public static final RegistryObject<Block> ROCK_BLOCK =
    BLOCKS.register("rock", () -> new Block(Block.Properties.create(Material.ROCK)));
BLOCKS.register(FMLJavaModLoadingContext.get().getModEventBus());   // 在 @Mod 构造器里
// ✅ 方式二：RegistryEvent.Register<T> —— #getRegistry 后 #register / #registerAll
@SubscribeEvent
public void registerBlocks(RegistryEvent.Register<Block> event) { event.getRegistry().register(...); }
// ✅ *Type 工厂：注册的是 TileEntityType / EntityType，不是 TileEntity / Entity 本身
REGISTER.register("example_tile", () -> TileEntityType.Builder.create(ExampleTile::new, EXAMPLE_BLOCK.get()).build(null));
// ✅ 引用原版对象
public static final RegistryObject<Item> BOW = RegistryObject.of(new ResourceLocation("minecraft:bow"), ForgeRegistries.ITEMS);
```

- `@ObjectHolder` 字段在其注册表的 `RegistryEvent$Register` 触发后注入。
- 自定义注册表：`RegistryEvent$NewRegistry` 里用 `RegistryBuilder#create` 建表并注册到 `RegistryManager`；值类型需实现 `IForgeRegistryEntry`（推荐继承 `ForgeRegistryEntry`）。
- ⚠️ 本档 `concepts_registries` **没有** `RegistryEvent$MissingMappings`、也没有 `DeferredRegister#makeRegistry` —— 两者只在 1.16.5 文档出现，不要写进 1.15.2 工程。

### 事件与总线

两条总线（`MinecraftForge.EVENT_BUS` 与 mod 总线）在 1.14.4 文档里已存在；1.15.2 的变化是 **`@Mod.EventBusSubscriber` 推荐写法收紧**为显式 `modid` + `bus`。

```java
// ✅ 1.15.2 events_intro 示例
@Mod.EventBusSubscriber(modid = "mymod", bus = Bus.FORGE, value = Dist.CLIENT)
public class MyStaticClientOnlyEventHandler {
    @SubscribeEvent public static void drawLast(RenderWorldLastEvent event) { ... }
}
// ❌ 1.14.4 文档旧写法：@Mod.EventBusSubscriber(Dist.CLIENT)   // 不写 modid / bus
```

- 生命周期与注册事件在 mod 总线：`@EventBusSubscriber(bus = Bus.MOD)` 或构造器里 `addListener`。
- 优先级 `EventPriority`：`HIGHEST` / `HIGH` / `NORMAL` / `LOW` / `LOWEST`。
- 可取消事件用 `@Cancelable` + `Event#setCanceled`；对不可取消事件调用抛 `UnsupportedOperationException`。

### 生命周期：并行派发与延迟队列

并行派发**不是** 1.15 新增（1.14.4 文档已说明各阶段全 mod 并发），变的是推荐的排队 API：1.14.4 文档 `DeferredWorkQueue` → 1.15.2 文档 `ParallelDispatchEvent#enqueueWork`。

| 事件 | 时机 / 说明（`1.15.2/concepts_lifecycle`） |
|------|---------------------------------------------|
| `RegistryEvent$NewRegistry` / `RegistryEvent$Register<?>` | 建表 / 每表一次注册，均同步触发 |
| `FMLCommonSetupEvent` | 双端公共动作（如注册 Capability） |
| `FMLClientSetupEvent` / `FMLDedicatedServerSetupEvent` | 各自物理端（键位、渲染层注册等） |
| `InterModEnqueueEvent` → `InterModProcessEvent` | `InterModComms#sendTo` → `InterModComms#getMessages` |
| `FMLLoadCompleteEvent` / `GatherDataEvent` | 加载结束 / 数据生成时最后触发且同步 |
| `FMLConstructModEvent` | 注册事件之前触发；1.16.5 文档明确标注它是 Forge 内部用途，mod 不要用 |

### Capability：签名收紧

| 1.14.4 文档 | 1.15.2 文档 |
|-------------|-------------|
| `ICapabilityProvider` 有 `hasCapability` + `getCapability` | 文档只保留 `#getCapability` |
| 第二参数 `EnumFacing` | 第二参数 `Direction`（传 `null` = 内部/与面无关的通用实例） |
| 返回能力实例本身 | 返回 `LazyOptional<T>`，不可用时为空 `LazyOptional` |
| — | 默认实例经 `Capability#getDefaultInstance` 取得 |

```java
// ✅ 1.15.2：@CapabilityInject 字段在未注册时保持 null；返回 LazyOptional<T>
@CapabilityInject(IItemHandler.class)
public static final Capability<IItemHandler> ITEM_HANDLER = null;
LazyOptional<IItemHandler> cap = someTileEntity.getCapability(CapabilityItemHandler.ITEM_HANDLER_CAPABILITY, Direction.NORTH);
// TODO(未核实): 文档只确认返回 LazyOptional，未给出消费它的具体方法名（勿凭记忆写 ifPresent 之类）
```

### Tag 与数据包 JSON

- 路径不变：`/data/<modid>/tags/blocks/...json` → `Tag<Block>`，ID 形如 `modid:foo/tagname`；原版键 `replace`。
- **Forge 扩展键：`optional`、`remove`**（`remove` 比 `replace` 更细粒度），适合做软依赖集成。
- 方块 / 物品 / 流体 tag 在登录与 reload 时同步给远端客户端；**函数 tag 不同步**。
- 查询：`BlockTags#getCollection` / `ItemTags#getCollection` → `TagCollection` → `Tag`，判员 `tag.contains(...)`、枚举 `tag.getAllElements()`；集合在 reload 后会失效，静态字段用 wrapper 规避。

```java
// ✅ 1.15.2 utilities_tags 示例
public static final Tag<Item> MY_TAG = new ItemTags.Wrapper(new ResourceLocation("mymod", "myitemgroup"));
boolean isInGroup = stack.getItem().isIn(MY_TAG);
// ❌ 1.14.4 文档示例：ItemTags.getCollection().getOrCreateTag(rl).contains(item);
```

### 物品属性与模型 override

```java
// ✅ 1.15.2 models_overrides：属性挂在物品上，getter（IItemPropertyGetter）参数 (ItemStack, World, LivingEntity) → float
this.addPropertyOverride(new ResourceLocation("pull"), (stack, world, entity) -> { /* ... */ });
```

```json
{ "parent": "item/generated", "textures": { "layer0": "examplemod:item/example_partial" },
  "overrides": [ { "predicate": { "examplemod:power": 0.75 }, "model": "examplemod:item/example_powered" } ] }
```

- 自定义属性名要带 modid 命名空间；只写 `property` 等价于 `minecraft:property`。`Item.Properties#maxDamage` 大于 `0` 时自动带上 `damaged` 与 `damage` 两个物品属性。
- 原版在物品构造器里注册属性（1.16 起改为集中注册，见本包 `1.16.x.md`——1.15.2 工程无该文档，勿跨档抄）。

### 网络（SimpleChannel）

```java
// ✅ 1.15.2 networking_simpleimpl：id++ 保证判别符唯一
//   三个函数依次为 BiConsumer<MSG, PacketBuffer> / Function<PacketBuffer, MSG> / BiConsumer<MSG, Supplier<NetworkEvent.Context>>
public static final SimpleChannel INSTANCE = NetworkRegistry.newSimpleChannel(/* ... */);
int id = 0;
INSTANCE.registerMessage(id++, MyMessage.class, MyMessage::encode,
    buf -> new MyMessage(buf), (msg, ctx) -> ctx.get().setPacketHandled(true));   // 文档未给解码样例
INSTANCE.sendToServer(new MyMessage());
HANDLER.sendTo(new MyClientMessage(), serverPlayer.connection.getNetworkManager(), NetworkDirection.PLAY_TO_CLIENT);
INSTANCE.send(PacketDistributor.PLAYER.with(serverPlayer), new MyMessage());
INSTANCE.send(PacketDistributor.TRACKING_CHUNK.with(chunk), new MyMessage());
INSTANCE.send(PacketDistributor.ALL.noArg(), new MyMessage());
```

- 版本兼容检查器要处理 `NetworkRegistry` 的「meta-versions」：`ABSENT`、`ACCEPTVANILLA`。
- 服务端防滥用：只在 `World#isBlockLoaded` 为真时访问方块 / 方块实体，否则可被利用做任意区块生成。

### 维度

本档语料**没有**维度专页。可核实的只有反向证据：1.16.5 primer 记录 `DimensionManager` 在 1.16 被移除，以及 1.16 失去「修改维度光照贴图」的 Forge 补丁（说明 1.15 及以下仍有该能力）。

### 构建可见事实

- MDK 严格必需项只有 `build.gradle`、`gradlew`、`gradlew.bat` 与 `gradle/` 目录；**不要改 `build.gradle` 的 `buildscript {}` 段**（ForgeGradle 依赖其默认内容）。
- 试跑 `gradlew runClient`，游戏从 `<runDir>` 启动；默认 MDK 只含 `main` source set。
- `mods.toml` 的 `loaderVersion` 形如 `"[31,)"`（本档 `00-project-setup` 规则：表示 Forge 31 及以上）。
- Java 8、`pack_format` 6（本档 `AGENTS.md` 基本信息表与版本差异表）。

## 1.15.x 与其他版本对比

| 项 | 1.14.4 | **1.15.2** | 1.16.5 |
|----|--------|------------|--------|
| 方块属性类型 | `IProperty<T>` | `IProperty<T>` | `Property<T>` |
| 状态容器方法 | `Block#fillStateContainer` | 同左 | `Block#createBlockStateDefinition` |
| 默认状态 | `Block#setDefaultState` | 同左 | `Block#registerDefaultState` |
| `*Type` 工厂 | `TileEntityType.Builder.create` | 同左 | `TileEntityType.Builder.of` |
| Capability 返回 | 实例本身 | `LazyOptional<T>` | `LazyOptional<T>` |
| Tag 成员查询 | `getOrCreateTag`（文档示例） | `ItemTags.Wrapper` + `Item#isIn` | `ITag` + `Item#is` |
| 延迟队列 | `DeferredWorkQueue` | `ParallelDispatchEvent#enqueueWork` | `enqueueWork` |
| 物品属性注册 | `Item#addPropertyOverride` | 同左 | `ItemProperties#register` |
| Java | 8 | **8** | 8 代码为基线（工具链口径见该档记录） |

## 对本档工程的影响

1. **渲染代码是第一嫌疑**：`GlStateManager` / `GL11` 直调、手写 `tessellator.draw()`、覆写方块渲染类型的方法都是 1.14→1.15 迁移残留，按上文表格改成 `RenderSystem` + `RenderType` + `MatrixStack` 批处理形态。
2. **不要给 1.15.2 工程写 1.16 的东西**：`Property<T>`、`createBlockStateDefinition`、`registerDefaultState`、`TileEntityType.Builder.of`、`ItemProperties#register`、`RegistryEvent$MissingMappings`、`GlobalLootModifierProvider` 在本档文档中都不存在。
3. **注册只有两条正路**，都挂 mod 总线；`Block.Properties` 本档用 `.create(Material)`，不是 `.of(...)`。
4. Tag JSON 用 Forge 的 `optional` / `remove` 扩展键做软依赖；成员判断写 `Item#isIn(Tag)`。
5. 拿不准就先 `search_forge_docs --version=1.15.2`；查不到留 `// TODO(未核实)`，**禁止**用 1.16.5 / 1.18.2 规则树补全本档代码。
