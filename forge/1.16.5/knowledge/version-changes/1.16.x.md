# 版本变更记录：1.16.x

## 1.16.5 Forge 概述

> 1.16 是本世代最大的一次断裂：大量注册对象**转为数据驱动**（Codecs + Dynamic Registries），维度 / 生物系 / 世界生成整体换成 JSON。注意断裂点其实落在**小版本 1.16.2**（primer 原话：「large breaking changes were made in a MINOR version, 1.16.2」）——1.16.1 与 1.16.5 不是同一片地形。

核实渠道：`get_migration_guide --route=1.15.2->1.16.5 --platform=forge`（found:true，source=primer，CC-BY-4.0 (50ap5ud5)），同内容文档页 `get_forge_doc_full --id=1.16.5/primer_1_16_5`；本节其余条目为 1.15.2 与 1.16.5 两套语料同名页的逐行差异。

## 核心变更（1.15.2 → 1.16.5）

### Codecs / DataFixerUpper

- DFU 升级带来 **Codecs**：Java ⇄ JSON 双向序列化桥；`BlockState`、`ResourceLocation`、世界生成对象都开始用 Codec。
- 陷阱：反序列化时**出错条目会被丢弃**，只返回 PartialResult；细节看 `latest.log` / `debug.log`。
- `UnboundedMapCodec` 对错误尤其敏感：遇出错条目会把它**之前**的条目一起丢掉（见 MC-197860）。

### 动态注册表与 RegistryKey

```java
// ✅ RegistryKey = 注册表 ID + 对象注册名，可用 == 比较
RegistryKey<Biome> key = RegistryKey.get(Registry.BIOME_REGISTRY, new ResourceLocation(MODID, "test_biome"));
Biome biome = serverWorld.getServer().registryAccess().registryOrThrow(Registry.BIOME).get(key);
// primer 原文在此处混用 Registry.BIOME 与 Registry.BIOME_REGISTRY，以你映射下的实际常量为准
// ✅ 维度引用改用 RegistryKey<World>（不再是 DimensionType）；MinecraftServer#getWorld 取 RegistryKey<World>
RegistryKey<World> dim = RegistryKey.get(Registry.DIMENSION_REGISTRY, new ResourceLocation(MODID, "my_dimension"));
ServerWorld world = server.getWorld(dim);
```

- 已数据驱动的注册表：`Dimension`、`DimensionType`、`Biome`、`ConfiguredFeature`、`ConfiguredStructureFeature`。
- 只有「要被已有注册表对象引用」时才需要代码注册，否则**推荐写 JSON**。
- ⚠️ **不要在客户端访问客户端不存在的那份动态注册表**（如 `ConfiguredFeature` 不在客户端），否则崩专用服务端。
- ⚠️ 服务端启动前不要取 `DynamicRegistries`；代码版世界生成对象必须在 `FMLCommonSetupEvent` 的 `event.enqueueWork(...)` 里放进 `WorldGenRegistries`，否则会挤掉其他 mod 的世界生成对象。

### 世界生成

| 对象 | 1.16.5 做法 |
|------|-------------|
| Biome | JSON：`data/<modid>/worldgen/biome/<name>.json`；代码版仍可行但不推荐（只适合占位 ID） |
| Feature | 构造器注册 `Feature<?>` 到 Forge 的 `FEATURES`；`FMLCommonSetupEvent` + `enqueueWork` 把 `ConfiguredFeature` 加进 `WorldGenRegistries`；`BiomeLoadingEvent` 塞入生物系 |
| Structure | 同上，Forge 注册表为 `STRUCTURE_FEATURES`；另需 `Structure.STRUCTURES_REGISTRY`、`FlatGenerationSettings.STRUCTURES`、`DimensionStructuresSettings.DEFAULTS`（不可变 Map，需 AT/Mixin/反射）、可选 `Structure.NOISE_AFFECTING_FEATURES`，并在 `WorldEvent.Load` 里加进 `ChunkGenerator` |
| 实体生成 | 改由 `BiomeLoadingEvent` 处理 |
| 树 | 拆成 `FeatureSize` / `TrunkPlacer` / `FoliagePlacer` / `FoliageAttachment`；1.15 的 FoliagePlacer 建议整段重写 |
| ChunkGenerator | 注册到 `WorldGenRegistries`，其构造需要一个 **Codec**；由维度 JSON 引用它 |

```java
// ✅ primer 原文示例：按生物系名匹配
@SubscribeEvent(priority = EventPriority.HIGH)
public static void onBiomeLoad(BiomeLoadingEvent event) {
    RegistryKey<Biome> eventBiomeKey = RegistryKey.get(Registry.BIOME_REGISTRY, event.getName());
    RegistryKey<Biome> target = RegistryKey.get(Registry.BIOME_REGISTRY, new ResourceLocation("minecraft", "plains"));
    if (eventBiomeKey == target) { /* ... */ }
}
// ✅ 加入主世界
public void commonSetup(FMLCommonSetupEvent event) {
    event.enqueueWork(() -> BiomeManager.addAdditionalOverworldBiomes(testBiomeKey));
}
```

- 生物系外观迁到 `BiomeAmbience`（水色、水雾、雾色、粒子、声音；声音分 loop / mood / additions），新增 `BiomeContainer`（下界生物系计算）。**`Biome#getRegistryName` 现在可能为 null**：取生物系一律用 `RegistryKey` 从动态注册表拿，**不要**用 ForgeRegistry 里那份（它不含 datapack 加的生物系）。
- 1.15.2 的 Forge 生物系钩子 **Edge / Ocean / Hills 已移除**；Nether / End / River 钩子本档缺失。
- 生物系内部 ID 退回整数，改 datapack 会造成旧存档 ID 漂移；vanilla 到 1.16.5 未修，Forge 已修。
- `BiomeLoadingEvent` 在 datapack 解析期触发，**SERVER 配置尚未初始化**，那时能用的只有 COMMON 配置。
- `SingleBiomeProvider` 取不到 `Biome.CODEC` 的生物系、颜色也传不对客户端；变通是喂单个生物系的 `MultiBiomeProvider`。

### 维度

- `Dimension` 变成「`ChunkGenerator` + `DimensionType` 的组合」（Mojang 名 `LevelStem`；`World` 对应 `Level`）；一个 `DimensionType` 可被多个维度复用，维度与 World 一对一。
- 注册全走 JSON：`data/<modid>/dimension/`、`data/<modid>/dimension_type/`。
- **Forge 的 `DimensionManager` 被移除**；取维度注册表（`MinecraftServer#worldData#worldGenSettings#dimensions`）只用于动态维度等特殊场景，一般取维度用 `ServerWorld#getLevel`。
- `DimensionRenderInfo` 通过 `DimensionType` 的 `"effects"` 字段绑定；vanilla 硬编码只认原版维度，自定义要 Mixin / AccessTransformer / 反射改其私有 Map，并在 `FMLClientSetupEvent` + `enqueueWork` 里塞。
- **1.16 失去 1.15 及以下的「修改维度光照贴图」Forge 能力**（Forge 补丁不再适用）。
- 弃用：`/forge setdimension`（改用原版 `/execute in`）、`forgeCloudsEnabled`。

### 注册与工厂方法

```java
// ✅ *Type.Builder 由 create 改名 of；Block.Properties 由 create 改名 of
REGISTER.register("example_tile", () -> TileEntityType.Builder.of(ExampleTile::new, EXAMPLE_BLOCK.get()).build(null));
BLOCKS.register("rock", () -> new Block(Block.Properties.of(Material.STONE)));
```

- 自定义注册表多一条路：`DeferredRegister#makeRegistry(name, builderSupplier)`，**必须先于**挂总线的 `#register` 调用；`#setName` / `#setType` 已默认填好，返回的是需 `RegistryEvent$NewRegistry` 后才能解析的 `IForgeRegistry`。
- 新增 `RegistryEvent$MissingMappings`：`#getMappings(modid)` 或 `#getAllMappings()` 处理被移除 / 改名的注册项。

### 方块状态：`IProperty` 家族改名

| 1.15.2 | 1.16.5 |
|--------|--------|
| `IProperty<T>`（`IntegerProperty` / `BooleanProperty` / `EnumProperty` 实现它） | `Property<T>`（同上三个实现 `Property`） |
| `Block#fillStateContainer(StateContainer.Builder)` | `Block#createBlockStateDefinition(StateContainer$Builder)` |
| `Block#setDefaultState(BlockState)` | `Block#registerDefaultState(BlockState)` |
| BlockState = (Block, properties, values) 三元组 | BlockState = (block, property→value 映射) 二元组 |

### Tag：接口整体换名

- `Tag` → `INamedTag`（JSON 声明出来的类型）、`TagCollection` → `ITagCollection`、`Tag` → `ITag`。
- `BlockTags#getCollection` / `ItemTags#getCollection` → **`#getAllTags`**；`tag.getAllElements()` → **`tag.getValues()`**。
- `Item#isIn(Tag)` → **`Item#is(ITag)`**。
- Forge 的 `optional` 数组**已废弃**，改为「原版的可选条目写法」。 <!-- TODO(未核实): 1.16.5 文档只写 deprecated in favor of the vanilla method，未给出该写法的 JSON 键名 -->
- 同步范围扩大：Block / Item / Fluid 之外新增 **EntityType**，Forge 另加 **TileEntityType / Potion / Enchantment**；函数（Function）tag 仍不同步。

### Capability

```java
// ✅ 失效钩子与脏标记改名
@Override public void invalidateCaps() { super.invalidateCaps(); /* 1.15.2 是 remove() */ }
this.setChanged();       // 1.15.2 是 markDirty()
```

### 网络

- `SimpleChannel#sendTo` 第二参数：`player.connection.getNetworkManager()` → **`player.connection.getConnection()`**。
- 服务端防任意区块生成的判据：`World#isBlockLoaded` → **`World#hasChunkAt`**。
- 注册表数据驱动化后，登录时服务端发一份注册表数据：客户端持有自己的维度列表与动态注册表副本（**不是全部**，如 `ConfiguredFeature` 不在客户端）。
- 新增多部件碰撞盒注册钩子（类似末影龙）；Forge ChunkManager 回归，可自建 ticking / non-ticking 区块票据。

### 渲染与物品属性

- 绝大多数渲染方法参数多了 `MatrixStack`；**GUI 是例外**，部分方法仍走 `RenderSystem` / `GlStateManager`。

```java
// ✅ 物品属性改为集中注册（FMLClientSetupEvent）；签名核实自 query_api --class=ItemProperties --version=1.16.5
//   → net.minecraft.client.renderer.item.ItemProperties：register(Item, ResourceLocation, ItemPropertyFunction) / registerGeneric(ResourceLocation, ItemPropertyFunction)
ItemProperties.register(myItem, new ResourceLocation(MODID, "power"), (stack, world, entity) -> 0F);
// 1.15.2 的 Item#addPropertyOverride + IItemPropertyGetter 已不是本档口径
```

### 实体属性、命令、ReloadListener、世界存档数据

- 实体属性不再来自实体类方法：构建后放进 `GlobalEntityTypeAttributes`；**mod 用事件**——`EntityAttributeCreationEvent`（自己的实体）、`EntityAttributeModificationEvent`（给已有实体加属性）；原版生物用静态 `createAttributes()` + `event.put(...)`。
- 命令注册迁到 `RegisterCommandsEvent`；`ReloadListener` 注册到 `AddReloadListenerEvent`。整局 datapack 至少重载两次，服务端启动前就会触发，里面要发包先判 `ServerLifecycleHooks#getCurrentServer` 是否为 null。
- 新增 `WorldSavedData` 体系：经 `DimensionSavedDataManager#computeIfAbsent` 取，入口是 `ServerChunkProvider#getDataStorage` 或 `ServerWorld#getChunkSource`；没创建过就不存在于该世界。

### DataGen 与全局战利品修正

| 项 | 1.15.2 | 1.16.5 |
|----|--------|--------|
| Tag provider 覆写点 | `TagsProvider#registerTags` | `TagsProvider#addTags` |
| Recipe provider 覆写点 | `RecipeProvider#registerRecipes` | 文档作 `#buildShapelessRecipes`（原文如此，用前请核） |
| Advancement provider | 有类但文档标注硬编码只服务原版进度 | 正式列出 `AdvancementProvider#registerAdvancements` |
| 全局战利品修正 provider | 无 | **`net.minecraftforge.common.data.GlobalLootModifierProvider`**，覆写 `#start` |

```json
{ "replace": false, "entries": [ "examplemod:example_glm", "examplemod:example_glm2" ] }
```

- 该文件是 `data/forge/loot_modifiers/global_loot_modifiers.json`，1.16.5 **只读 forge 命名空间**这一份。
- `replace` **必须存在**：`false` 追加（mod 为兼容性应取 `false`），`true` 整体替换（datapack 覆盖场景）。
- `entries` 是**有序**列表，每项指向 `data/<namespace>/loot_modifiers/<path>.json`（解决多 mod 冲突）。
- 单个修正器 JSON 新增 `"type": "examplemod:example_loot_modifier"`（即序列化器名）。
- 代码侧改为：实现 `IGlobalLootModifier`（多数情况继承带基础功能的 `LootModifier`）+ 实现 `GlobalLootModifierSerializer`，后者像其他 `IForgeRegistryEntry` 一样注册。

### mods.toml / 映射 / 工具链

- **1.16.5 起 `mods.toml` 必须写 `license` 字段**（许可证名或自定义许可 URL）。
- `@Mod.EventBusSubscriber` 有 bug：不写 `modid` 时事件可能不知道该谁触发，一律 `@Mod.EventBusSubscriber(modid = MyMod.MODID)`。
- MDK 默认改用 **Mojang 官方映射（Mojmap）**：方法 / 字段用官方名，**类名仍是 MCP 名**（1.17 才全换）。转换：`gradlew -PUPDATE_MAPPINGS_CHANNEL="official" -PUPDATE_MAPPINGS="1.16.5" updateMappings`，随后 `mappings channel: "official", version: "1.16.5"`（同一文档另一处把任务写作 `upgradeMappings`，以本地 Gradle 任务名为准）。
- 想退回 MCP：`mappings channel: 'snapshot', version: '20210309-1.16.5'`（文档称这很可能是最后一批 MCP 映射）。
- **1.16+ Forge 原生支持 Mixin**；文档定位是「最后手段」，优先要 Forge 钩子。
- Forge 产物的 **Maven 仓库地址变了**：老工程要更新 `build.gradle` 里所有 maven url（新 MDK 已备好，文档未给具体 URL）。
- 工具链口径已按官方 MDK 对齐，**残留偏差照实记录**：primer 记「支持 Java 15 与 Gradle 6.8，但代码必须仍是 Java 8」；官方 `forge-1.16.5-36.2.34-mdk.zip` 的 `build.gradle:19` = `JavaLanguageVersion.of(8)` + ForgeGradle `5.1.+` + Gradle 7.3.3。本档 `AGENTS.md` / `00-project-setup.mdc` / `scaffold/build.gradle` 的 Java 已统一为 8；**未改**的是 scaffold 仍钉 FG `[4.1,4.2)` + Gradle 7.6（与 MDK 不同源，改动需真跑 `gradlew build` 佐证，本机离线且无 JDK 11）。以你工程实际配置为准。
- `FMLConstructModEvent` 被标为 Forge 内部使用，mod 不要用。

## 对本档工程的影响

1. **先判定你在 1.16 的哪一段**：1.16.2 才是数据驱动断裂点，`1.15.2->1.16.5` primer 的内容不要往 1.16.1 工程上套。
2. **生物系 / 维度以 JSON 为主**（`worldgen/biome`、`dimension`、`dimension_type`）；代码对象一律 `WorldGenRegistries` + `FMLCommonSetupEvent#enqueueWork`，漏写会挤掉别的 mod 的世界生成。
3. **一批机械改名要扫**：`IProperty`→`Property`、`fillStateContainer`→`createBlockStateDefinition`、`setDefaultState`→`registerDefaultState`、`Builder.create`→`Builder.of`、`markDirty`→`setChanged`、`remove()`→`invalidateCaps()`、`getAllElements()`→`getValues()`、`isIn`→`is`、`getNetworkManager()`→`getConnection()`、`isBlockLoaded`→`hasChunkAt`、`addPropertyOverride`→`ItemProperties.register`。
4. **实体属性 / 命令 / reload listener 全改事件驱动**：`EntityAttributeCreationEvent`、`EntityAttributeModificationEvent`、`RegisterCommandsEvent`、`AddReloadListenerEvent`。
5. `mods.toml` 缺 `license` 在本档即不合规；`@Mod.EventBusSubscriber` 一律带 `modid`。
6. 本档语料**没有** Container/Screen 专页（`search_forge_docs --query=containers` 返回空，`query_api --class=ContainerType --version=1.16.5` 亦 `found:false`），菜单类只按本档 `10-gui` 规则走，查不到的名字留 `// TODO(未核实)`，不要从 1.18.2 / 1.20.1 抄 `MenuType` / `IForgeMenuType`。
