# Minecraft 1.20.4 → 1.21.1 版本变化（Fabric 1.21.1 档）

> 本文件 2026-09-05 新建，补本档自身缺失的迁移面：同目录原有 `1.20.x.md`（md5 `f298626b89d968277feb63c5cf28e353`，标题《1.19.x → 1.20.x 版本变化》）讲的是 **1.19 → 1.20**，不覆盖 1.20.4 → 1.21.1。
>
> 证据只取仓内语料两版对照：`data/fabric_1.21.1/`（官方 fabric-docs 1.21.1 页 + `yarn-1.21.1+build.3-tiny.gz`）与 `data/fabric_1.20.4/`（同两样）。`.md` 行号指各版 `fabric-docs/<ver>/raw/`。
>
> 本文件不写未在此出现的类 / 方法名。需要更多口径 → `search_fabric_docs version=1.21.1`；Yarn 名核对 → `convert_mapping` 或本档 tiny。**禁止**克隆 `fabric/1.21.11/knowledge/version-changes/1.21.x.md` 顶数（该档 1.21.11 的口径含 `RegistryFixedCodec` 等 1.21.2+ 变化，与本档不同）。

## 1. 迁移基线

- 官方迁移文档的口径就是 **1.20.4 → 1.21.1**，且明确「1.21.1 是 1.21 的 hotfix，文档按 1.21.1 写，不再单独跟 1.21」：CORPUS `data/fabric_1.21.1/fabric-docs/1.21.1/raw/develop_porting_index.md:22,28`。
- 本档 `knowledge/version-changes/1.20.x.md` 的角色因此不变：它只答「从 1.19.x 上来怎么改」；答「往 1.21.x 上去怎么改」看本文件。

## 2. Java / 构建脚本

**已知矛盾（未改，登记）**：`data/fabric_1.21.1/meta.json` 的 `"compatibilityLevel": "JAVA_17"` 与上面官方文档 + 本档 `scaffold/README_AI.md:7`（Java 21）冲突。该文件自称「工具不读取此文件，仅供人工参考」，实测 `mcp-server/src` 与 `mcp-server/scripts` 对 `compatibilityLevel` 命中 0 → 不影响任何工具行为，但**别拿它当 Java 口径**。

> 本仓不代跑 Gradle（人在环）。上面两条命令由用户在自己的工程里执行。

## 3. 数据组件（本区间最大变化）

- `net/minecraft/component/` 包在 1.20.4 的 Yarn 映射里**整包不存在**（CLASS 唯一名 0 个）→ 1.21.1 有 67 个 CLASS，其中 `component/type/` 47 个。
- 1.21.1 的 Yarn 名字口径（tiny 实测）：
  - 存在：`net/minecraft/component/ComponentType`、`net/minecraft/component/DataComponentTypes`（**复数**）、`net/minecraft/component/ComponentMap`、`net/minecraft/component/ComponentChanges`、`net/minecraft/component/type/FoodComponent`
  - **不存在**独立类 `DataComponentType`（该串只作为 `DataComponentTypes` 与 `ComponentType$Builder$SimpleDataComponentType` 的一部分出现）
  - 注册表键：`Registries.DATA_COMPONENT_TYPE` 在 1.21.1 tiny 有、1.20.4 tiny 无
- ⚠ 抄语料正文会写出错的映射名：`data/fabric_1.21.1/.../develop_items_custom-data-components.md:28,48` 的正文写 `DataComponentType`，而同页 `:37` 的代码块与 `:117` 的报错串是 `ComponentType`；`:38` 还漏进 Mojmap 名 `BuiltInRegistries`（Yarn tiny 实测 0 命中）。同一现象在 `develop_codecs.md`（3 处）、`develop_sounds_custom.md`（1 处）也有，且 1.20.4 语料已有 → **不是 1.21 引入的变化，是语料本身混映射**。本档映射是 Yarn，方法名以 tiny 为准。
- `ItemStack` 读组件三式（CORPUS 同页 `:83` `stack.get(...)`、`:143` `getOrDefault(..., default)`、`:153` `stack.has(...)`）。
- 本档规则树现状：`.cursor/rules/*.mdc` 对 `ComponentType` / `DataComponentTypes` 命中 **0**；唯一已落地的组件面是 `.cursor/skills/mc-item.md:44`——`FoodComponent` 在 `net.minecraft.component.type`、Builder 用 `.nutrition(int)`，与 tiny 实测一致。自定义组件注册写法在本档规则里尚未展开，见本档 `pack.meta.json` 的 `gaps`。

## 4. 附魔：从「继承子类」改为「数据驱动效果」

- Yarn tiny 实测：`net/minecraft/enchantment/` 下的具名 `*Enchantment` 子类 1.20.4 = **31 个** → 1.21.1 = **0 个**；1.21.1 新增 `enchantment/effect`（含 `effect/entity`、`effect/value`）与 `enchantment/provider` 子包共 **39 个** CLASS，另有 `EnchantmentEffectComponentTypes`。
- 结论：在 1.21.1 上「新建附魔 = `extends EnchantmentXxx`」这条路的父类**全部不存在**。1.21 附魔是数据包注册 + 效果组件组合，本档语料有专页：`data/fabric_1.21.1/.../develop_items_custom-enchantment-effects.md`（章节 `:28` 自定义效果 / `:40` 注册效果 / `:46` 创建附魔）；1.20.4 语料**无此页**。
- 本档 `.cursor/skills/mc-enchantment.md` 是骨架（无任何 API 名，因此也**不教**旧的继承写法），但未接上第 4 节的新机制 → 记进 `gaps`。

## 5. 网络：`PacketCodec` / `RegistryByteBuf` 化

- Yarn tiny 实测：1.20.4 的 `net/minecraft/network/` 下**没有** `codec/` 与 `state/` 子包；1.21.1 有 `network/codec/PacketCodec`、`network/RegistryByteBuf`、`network/state/PlayStateFactories` 等；1.21.1 另有 `NetworkPhase`、`DisconnectionInfo`、`NetworkStateBuilder`（1.20.4 无）。
- 本档规则已按 1.21.1 口径落地：`.cursor/rules/06-networking.mdc:7-8`（Yarn 用 `CustomPayload` + `PayloadTypeRegistry.playC2S()/playS2C()`，并显式禁用 `FabricPacket` / `s2c()` / `c2s()` / `CustomPayloadRegistry`）、`:23-26`（`RegistryByteBuf` + `PacketCodec` + `PacketCodecs` 导入）、`:44-54`（注册与发送）。
- 注意：1.21.1 语料**没有** networking 专页（45 页里无 `develop_networking*`）→ 网络口径的语料依据只有本档规则 + Fabric API 摘要，别假设「文档页里能找到」。

## 6. 语料覆盖差（判断「本档有多少新专题」用）

`data/fabric_1.20.4/fabric-docs/1.20.4/raw/` 31 页是 `data/fabric_1.21.1/fabric-docs/1.21.1/raw/` 45 页的**真子集**（只在 1.20.4 出现的页 = 0）。1.21.1 新增 14 页：

`develop_porting_index` · `develop_items_custom-data-components` · `develop_items_custom-enchantment-effects` · `develop_blocks_block-entities` · `develop_blocks_block-entity-renderer` · `develop_data-generation_setup` · `_advancements` · `_loot-tables` · `_recipes` · `_tags` · `_translations` · `develop_sounds_dynamic-sounds` · `develop_automatic-testing` · `develop_ide-tips-and-tricks`

其中 datagen 一次补齐 6 页 = 1.21 侧 DataGen 口径变化的入口。本档 `07-datagen.mdc`（223 行）已按 1.21 族 API 写：`:11` `DataGeneratorEntrypoint.onInitializeDataGenerator`、`:34` `FabricRecipeProvider` + `ShapedRecipeJsonBuilder.offerTo`、`:28,90-91` `FabricModelProvider` 构造收 `FabricDataOutput`、`:37,132` `FabricBlockLootTableProvider`、`:31,148,163` `FabricLanguageProvider`、`:14` 显式禁 Mojmap 的 `buildRecipes`。对照 6 页语料，本档规则未展开的两类 = advancement 数据生成与音效（含 1.21 的动态音效）：`.cursor/rules/*.mdc` 中 `Advancement` / `Sound` 命中 0 → 走上面语料页或 `search_fabric_docs version=1.21.1`。
