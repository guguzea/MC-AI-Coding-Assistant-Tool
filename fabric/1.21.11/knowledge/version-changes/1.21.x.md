# Minecraft 1.21.x 版本变更

> 本文件记录从 Minecraft 1.20.x 到 1.21.x 的关键变更，适用于 Fabric 1.21.11。

## 1.21.0 主要变更

### 网络通信 API 变化（重要）

1.21.x 对网络通信系统进行了重大重构：

| 旧方式（1.20.x） | 新方式（1.21.x） |
|------|------|
| 不要再用 `FabricPacket` 接口 | `CustomPayload` 接口 |
| `Identifier` 基于的注册 | `PayloadTypeRegistry` + `PacketType` |
| `Packet` 类 | `CustomPayload` record |

**新网络通信示例**：

```java

import net.minecraft.network.RegistryByteBuf;
import net.minecraft.network.codec.PacketCodec;
import net.minecraft.network.codec.PacketCodecs;
import net.minecraft.network.packet.CustomPayload;
import net.minecraft.util.Identifier;
import net.fabricmc.fabric.api.networking.v1.PayloadTypeRegistry;
import net.fabricmc.fabric.api.networking.v1.ServerPlayNetworking;
import net.fabricmc.fabric.api.networking.v1.ClientPlayNetworking;

public record MyPayload(int data) implements CustomPayload {
    public static final CustomPayload.Id<MyPayload> ID =
        new CustomPayload.Id<>(Identifier.of(MOD_ID, "my_packet"));
    public static final PacketCodec<RegistryByteBuf, MyPayload> CODEC =
        PacketCodec.tuple(PacketCodecs.VAR_INT, MyPayload::data, MyPayload::new);

    @Override
    public Id<? extends CustomPayload> getId() {
        return ID;
    }
}

PayloadTypeRegistry.playC2S().register(MyPayload.ID, MyPayload.CODEC);
PayloadTypeRegistry.playS2C().register(MyPayload.ID, MyPayload.CODEC);

ServerPlayNetworking.registerGlobalReceiver(MyPayload.ID, (payload, context) -> {
    int value = payload.data();
});
ClientPlayNetworking.registerGlobalReceiver(MyPayload.ID, (payload, context) -> {
    int value = payload.data();
});

ServerPlayNetworking.send(player, new MyPayload(123));
ClientPlayNetworking.send(new MyPayload(123));
```


### Attachment API（替代 Capability）

1.21.x 移除了旧版 Capability API，统一使用 Attachment API：

```java
import net.fabricmc.fabric.api.attachment.v1.AttachmentRegistry;
import net.fabricmc.fabric.api.attachment.v1.AttachmentType;
import net.minecraft.util.Identifier;

public static final AttachmentType<Integer> CLICKS =
    AttachmentRegistry.create(Identifier.of(MOD_ID, "clicks"));

entity.setAttached(CLICKS, 1);
Integer n = entity.getAttached(CLICKS);
```

### 数据生成器变化

- `LootTableProvider` 略有调整
- `FabricRecipeProvider` 保持类似接口
- `TagProvider` API 可能有细微变化

## 1.21.1 变更

| 变更 | 说明 |
|------|------|
| 性能优化 | 改善了渲染性能 |
| Bug 修复 | 修复了多个崩溃问题 |
| 网络同步 | 修复了数据包同步问题 |

## 1.21.3 / 1.21.11

以工程 `gradle.properties` 与 `list_fabric_versions` 为准。不要把 1.21.1 的 Fabric API 坐标抄到 1.21.11，也不要把 26.1 文档当 Yarn。


## 1.21.11 变更

| 变更 | 说明 |
|------|------|
| Yarn 映射 | 1.21.11+build.6 |
| Java 要求 | 必须 Java 21 |
| Fabric Loader | 0.16.x |

## 通用注意事项

### Fabric 开发注意点

- **Yarn 映射版本**：每个 MC 版本需要对应版本的 Yarn 映射
- **Fabric API / Loom**：用本档 MDK 的 `gradle.properties`，不要抄邻版坐标
- **Java 版本**：1.21.x 必须使用 Java 21

### 数据包兼容性

- `type` 字段仍然是**必需**的
- pack_format 34 适用于 1.21.x
- Attachment API 完全替代 Capability

## 升级建议

1. **测试优先**：每次 MC 版本升级前，先在小规模项目中测试
2. **Java 版本**：确保使用 Java 21
3. **映射更新**：同时更新 Yarn/Parchment 映射版本
4. **API 更新**：Fabric API 也需要对应版本升级
5. **网络代码**：如果使用网络通信，需要完全重写为新 API
