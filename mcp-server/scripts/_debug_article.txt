<div class="theme-doc-markdown markdown"><header><h1>Registries</h1></header>
<p>Registration is the process of taking the objects of a mod (such as <a class="" href="/docs/items/">items</a>, <a class="" href="/docs/blocks/">blocks</a>, entities, etc.) and making them known to the game. Registering things is important, as without registration the game will simply not know about these objects, which will cause unexplainable behaviors and crashes.</p>
<p>A registry is, simply put, a wrapper around a map that maps registry names (read on) to registered objects, often called registry entries. Registry names must be unique within the same registry, but the same registry name may be present in multiple registries. The most common example for this are blocks (in the <code>BLOCKS</code> registry) that have an item form with the same registry name (in the <code>ITEMS</code> registry).</p>
<p>Every registered object has a unique name, called its registry name. The name is represented as an <a class="" href="/docs/misc/identifier"><code>Identifier</code></a>. For example, the registry name of the dirt block is <code>minecraft:dirt</code>, and the registry name of the zombie is <code>minecraft:zombie</code>. Modded objects will of course not use the <code>minecraft</code> namespace; their mod id will be used instead.</p>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id="vanilla-vs-modded">Vanilla vs. Modded<a href="#vanilla-vs-modded" class="hash-link" aria-label="Direct link to Vanilla vs. Modded" title="Direct link to Vanilla vs. Modded" translate="no">​</a></h2>
<p>To understand some of the design decisions that were made in NeoForge&#x27;s registry system, we will first look at how Minecraft does this. We will use the block registry as an example, as most other registries work the same way.</p>
<p>Registries generally register <a href="https://en.wikipedia.org/wiki/Singleton_pattern" target="_blank" rel="noopener noreferrer" class="">singletons</a>. This means that all registry entries exist exactly once. For example, all stone blocks you see throughout the game are actually the same stone block, displayed many times. If you need the stone block, you can get it by referencing the registered block instance.</p>
<p>Minecraft registers all blocks in the <code>Blocks</code> class. Through the <code>register</code> method, <code>Registry#register()</code> is called, with the block registry at <code>BuiltInRegistries.BLOCK</code> being the first parameter. After all blocks are registered, Minecraft performs various checks based on the list of blocks, for example the self check that verifies that all blocks have a model loaded.</p>
<p>The main reason all of this works is that <code>Blocks</code> is classloaded early enough by Minecraft. Mods are not automatically classloaded by Minecraft, and thus workarounds are needed.</p>
