# Fabric 26.3 博客级迁移摘要

**这不是 docs 正文。** 上游 `FabricMC/fabric-docs` 的 26.3 移植 PR（**#738 PORT TO 26.3**）截至 2026-10-31 仍是 **Open（7/9）**：`versions/26.3` 不存在、`reference/latest` 仍是 26.2、站点 `/develop/` 标题仍是 26.2、`/26.3/` 404。
本页内容全部来自官方博客 **《Fabric for Minecraft 26.3》（2026-09-15，与 MC 26.3「Wilderness Bound」同日）**，只能当「改了什么」的清单，不能当类签名出处。

## 构建

- 博客撰写时：Loom **1.17**、Gradle **9.6.0**、Loader **0.19.5**（玩家端）
- 官方模板 `fabric-example-mod` 的 **26.3 分支**当前真值：`minecraft_version=26.3` / `loader_version=0.20.1` / `loom_version=1.19-SNAPSHOT` / `fabric_api_version=0.165.0+26.3`
- 博客**没有**给 Fabric API 版本号，**没有**说 JDK 版本

## Fabric API 被删（原版重构所致）

| 被删 | 替代 |
|---|---|
| `CompostingChanceRegistry` | `DataComponents.COMPOSTABLE` 或 `DefaultItemComponentEvents.MODIFY` |
| `FuelRegistry` | `DataComponents.COOKING_FUEL` / `BREWING_FUEL` |
| `FabricPotionBrewingBuilder`（含 `BUILD` 事件） | 酿造配方改数据驱动 JSON（`recipe` 目录，可用 datagen） |
| `StrippableBlockRegistry` / `TillableBlockRegistry` / `FlattenableBlockRegistry` | `BlockTransformerHelper`（如 `registerTilling`）+ `BlockTransformerEvents.MODIFY` |
| `FluidVariantAttributes#enableColoredVanillaFluidNames` | `FluidVariantAttributes#getColoredName`（按 mod 生效，不再整包开关） |
| 所有 `Block` 的 `Codec` + `block_type` 注册表 | 无（整体删除） |

## Fabric API 新增

- **`FluidFlowCallback.EVENT`**：流体尝试蔓延 / 液体方块被放置 / 液体方块邻居更新时触发；返回 `true` 放行、`false` 取消（博客示例：蓝冰上方生成冰）
- 流体行为 API **不再 experimental**，新增 `isInFluid` / `onFluidEntered` / `onFluidExited` 控制方法
- **`DynamicRegistries.registerReloadable(RELOADABLE_REGISTRY_KEY, ReloadableRegistryObject.CODEC)`**
- **`TooltipFlag#shouldDisplayAllInformation`**（Fabric 与 NeoForge 共同新增，配方查看器可索引被按键门控的 tooltip）
- **`Block#getProvidedEnchantmentPower`**（自定义方块指定提供的附魔之力）
- `BlockTransformerHelper.registerTilling(...)` + `BlockTransformerEvents.MODIFY`（签名形如 `(key, transforms, source, registries)`）

## 原版侧（非渲染部分，博客只列主要项）

1. **燃料 / 堆肥 / 酿造燃料组件化**：`DataComponents.COMPOSTABLE` / `COOKING_FUEL` / `BREWING_FUEL`，值是**数据驱动的 number provider**（`ResolvableInt` / `ResolvableFloat` + `ContextFloatProviders.*`）
2. **酿造配方数据驱动**：进数据包 `recipe` 目录
3. **Block transformers**：新原版数据类型，JSON 放 `block_transformer` 目录，物品用 `DataComponents.BLOCK_TRANSFORMER` 关联；mod 只能「扩展/修改」，新建必须走 JSON
4. **动态注册表**：现在包含 recipes 与 advancements，统一走动态注册表加载路径
5. **Configured features**：移到 `worldgen/feature`；`Feature` 与 `FeatureConfiguration` 合并为新 `Feature` 接口；codec 注册到 **`BuiltInRegistries.FEATURE_TYPE`**（不再是 `FEATURE`）；数据里不再有 `config` 包裹层
6. **Surface rules → Material rules**：改名并可注册（`worldgen/material_rule`），不必覆盖整个 Overworld 维度
7. **Material conditions** 可注册（`worldgen/material_condition`）
8. **Number providers** 拆 float / int 两类并可注册（`context_float_provider` / `context_int_provider`）；新增 `/compute` 命令
9. **Block state providers** 可注册（`worldgen/block_state_provider`），部分类型去掉冗余后缀
10. **GLFW → SDL**：输入常量变了（**包括所有鼠标按键**），**不要硬编码**；自定义文本输入控件必须通知 `TextInputManager`，否则字符输入完全失效：
    - `Minecraft.getInstance().textInputManager().onTextInputFocusChange(isFocused)`
    - 实现 `GuiEventListener` 时可用 `Minecraft.getInstance().onTextInputFocusChange(this, isFocused)`
11. **渲染**：博客明确「未逐条列出」，指向 NeoForge 的 26.2→26.3 primer

## 使用边界

- 本页**不是** `data/fabric_26.3` 语料：没有 105 页正文、没有 `reference/latest` 源码、没有 loader-api 26.3 摘要。
- 类名与签名**不要**从本页抄：要核签名，走 `query_loader_api`（需自备 26.3 的 fabric-api jar）或等 #738 合并后重建语料。
