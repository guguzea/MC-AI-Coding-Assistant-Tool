# Agent 使用社区短文时的规则

适用：`community_knowledge/authored/`、`permitted/`、`links/`，以及 MCP `search_community_docs` / `get_community_doc_*`。

## 定位

- 社区短文 = **实务清单、反模式、工程化提示**，不是 API 规范。
- **注册 / 方法签名 / 事件总线细节** → 仍用 `search_forge_docs` / `search_fabric_docs` / `search_neoforge_docs`。`query_api` 只覆盖 Vanilla Parchment（约 1.16.5–1.20.4）
- 本仓库整体是**人在环**副驾驶：创意、兼容取舍、API 选择、性能与调试由用户拍板；写盘 / Gradle / 拷 jar / 上传须确认。

## 用前先对版本（强制）

社区短文是**按某一版本段核实的教学快照**，不是跨版本通用的 API 规范。引用任何 `authored/` / `permitted/` 条目前：

1. 先确认工程实际的 **MC 版本与加载器**（根 AGENTS.md 第一步），再对照短文 frontmatter 的 `mcHint`；
2. 不匹配 → 查本 README「版本路由矩阵」换同主题的正确篇目；没有对应篇 → 降级为**只参考思路**，API 名/签名一律以当档 `search_*_docs` 或官方文档为准；
3. 短文中的代码示例是讲解载体，禁止不经版本核对直接照抄进工程；
4. 版本边界敏感的断层（1.20.4→1.20.5 网络/数据组件、1.20.6→1.21.5 SavedData、1.20→1.21 附魔、1.21→26.x 渲染器）在相关短文内有对照表——引用时以表格标注的适用侧为准。

## 强制：不清楚就去查原文

当 Agent **已经引用或准备依据**某篇社区短文写代码 / 给方案，且出现下列任一情况时，**必须先打开原文或官网再继续**，禁止用「大概记得」硬编：

1. 短文写「以官方为准 / 名称以映射为准 / 版本相关」且当前细节不确定  
2. 短文只有要点或伪代码，缺少你要用的具体方法名、参数、事件名  
3. 用户现象与短文自检清单对不上，或短文未覆盖该症状  
4. 短文互相交叉引用（如机器 → Menu → Capability），你还没读关联篇就动手  
5. `links/` 类条目（仅有 URL、无正文）— **只能打开外链阅读**，禁止假装已有全文许可去「复述整页」

### 原文从哪来

| 来源 | 做法 |
|------|------|
| 短文末「不清楚时」或 frontmatter 给出的 URL | 用浏览器 / `WebFetch` 打开该页 |
| `permitted/`（如 3993） | 与 `links/` 相同：**仅指针**（ATTRIBUTION + 原文 URL），不入库正文；不确定时打开帖内原文 URL |
| `links/`（如 6071） | **仅浏览** https://www.mcmod.cn/post/6071.html 等；**禁止把网页正文拷进仓库或长篇复述** |
| API / 类名 | `search_*_docs`、`get_*_doc_full`、`query_api` — 不要用社区短文代替 |

### 输出时

- 可以说「按社区短文 X + 官方文档 Y」。  
- 若刚查了原文，用一句话标明依据（链接或文档标题），避免 silently 编造。

### URL 形态判据台账（误判机制的纠错登记处）

审计社区条目里的 URL 时，**先按路径段核形状，再判坏链**。已发生过一次机制误判，记在这里免得重犯：

| 机制（错在哪） | 实况（可打开核对） | 纠正后的判据 | 404 与否 |
|---|---|---|---|
| 「`authored/saveddata-world-persistence.md:113` 的 URL 缺前导 `/docs/` ⇒ 判坏链」——**该机制的错法仍成立**：按首段判必然误伤版本存档行，但本行首版给出的「两套形状都合法」结论是**形状推断、非取证** | **2026-09-24 已 curl 取证**（命令：`curl.exe -s -o /dev/null --ssl-no-revoke -w "%{http_code}" -L --max-time 25 <URL>`）：`…/1.20.4/docs/datastorage/saveddata/` ⇒ **404** ／ `docs.neoforged.net/docs/1.20.4/datastorage/saveddata/` ⇒ **200** ／ `docs.neoforged.net/docs/datastorage/saveddata/`（latest）⇒ **200**。同文件 `:112` 的 latest 形状本来就对，`:113` 已改为 200 那条 | 版本存档的合法形状 = `docs.neoforged.net/docs/<版本>/<路径>`（`/docs/` **恒在最前**，版本号在它后面）；`/<版本>/docs/<路径>` 实测 **404**，不是合法形状。latest = `/docs/<路径>` 仍合法。⇒ 判坏链**只能**跑一次 HTTP 码，不能由形状推 | **已取证**（404，2026-09-24，命令见左）⚠️ **本行 2026-09-24 首版用形状推断代替取证（当时写「两套形状都合法」并把本列留作 `未核实`），已被 curl 证伪**；留痕不删，作为「假设当证据」的复发样本 |

### 外部链接存活判定：按主机分判据（2026-09-24 用户裁定 + 实测）

- **风控型主机（`www.mcmod.cn` 等）：脚本探测结果不得当死链结论。** 实测本仓确证存在的
  `post/3993.html` 用 curl 返回 **403**（风控页）、`class/1.html` 三趟为 **429 / 403 / 403**（**同一 URL 的码在趟与趟之间漂移**）、`post/6071.html` 返回 **429**
  ⇒ 403/429/404 三者不可分辨，任何「mcmod 链接已失效」的判定都属**未核实**。
  要判活：用 **IDE 内置浏览器 / computer use** 逐条打开（2026-09-24 裁定：此类不修、按反爬关闭）。
- **`github.com` 等不拦脚本的：404 就是真失效**，不得套用上面那条依据。实测同客户端
  85 条去重 URL 得 72×200 / 13×404（该趟 0 条 `000`；复测死链 3/4 仍 404）。
- ⚠️ **把死链当内容引用的例外**：`authored/lib-traps-2026.md:59`（「访问这三个库的 Modrinth 页面返回
  404 / 已下架，旧链接全部失效」）与 `authored/library-catalog-2026.md:101`（「Modrinth 已下架(404)」）
  是**故意记录该资源已失效**，属正文、属正确；判据只针对「把失效链接当可用出处推荐给用户」。
- **上面两条主机判据都不是恒真的，按趟重测（2026-09-25 全量复测）**：本机系统代理 `127.0.0.1:7897` 开着，
  但 `curl.exe` **不读 Windows 系统代理**（env 里 `HTTP(S)_PROXY` 为空 ⇒ 直连），所以「脚本探测」默认走的是直连线路。
  带 `--proxy http://127.0.0.1:7897` 复测本仓 6 张文档面 **266 条去重 URL**（已把中文括号 / `<占位>` 从 URL 上切干净）：
  **258 条 2xx/3xx**，`www.mcmod.cn` 本趟 **104/104 全部 200**，且对照组 `post/99999999.html` / `class/9999999.html`
  返回 **404**（正文标题「出现错误!」）⇒ 本趟 mcmod 的 200 **有判别力**，与 09-24 那趟的 403/429 漂移并不矛盾：
  **风控是否触发随线路/时段变，所以「单趟不得定论」是纪律，「该主机永远不可脚本判」不是事实。**
  同趟另有一类必须与反爬分开：**`docs.geckolib.com` / `docs.kubejs.com` 是 NXDOMAIN / 无 A 记录（DoH `Status=3`），属域名真没了**，
  不是风控——这类要改指针，不该按「反爬不修」关闭。`docs.hmcl.net` 反过来：直连 **200** 而走梯子 **000**（TLS 握手失败）
  ⇒ **同一条 URL 在两条线路上结论相反**，任何 `000` 都必须换机制复测后才许写进报告。
