# mc-handoff — 会话交接

一句话目标：让一个**零本会话记忆**的接手者（可能就是下个会话里的你）只拿交接文档就能从中断处继续。

## 文档结构（六块都要，空了就写「无」）

1. **目标与现状** —— 一段话讲清在做什么 + 一句话「此刻进行到哪」。
2. **已落改动** —— 文件路径清单，每条一句「为什么」；注明哪些已提交、哪些只在工作区。
3. **证据指针** —— 本轮跑过的命令 / 测试 / 游戏实例的产物在哪：路径、退出码、关键读数（带口径与时间）；崩溃日志路径；哪些结论有证据、哪些只有口头。
4. **未做清单** —— 没做的每条附原因（等拍板 / 需授权 / 已知阻塞 / 主动跳过）。授权了但没执行的也算这条。
5. **下一步** —— 有序、可执行：命令、期望看到什么、失败长什么样。
6. **踩坑备忘** —— 只写本件事特有的陷阱：环境差异、假绿假红、口径陷阱、之前试错失败的路径（防止接手者重蹈）。

## 规则

- 只写本轮**真实发生过**的事实；没核实的一律进「未核实」并在第 4 块点名，禁止用记忆或推测填空白。
- 写给「新人」也能读：不写只有原会话懂的私有简写；每个自造名词首次出现带一句解释。
- 长度上限约 120 行。写超 = 你在记过程而不是记状态；把过程删掉，留状态。
- **每个提交落点带前进指针**：本轮真实发生过提交（由用户执行）时，给提交信息建议带一行「blockers / 留给下一轮」——卡在哪、下一步先做什么。提交信息是微交接，补两次交接文档之间的连续性；它有这行后，文档第 5 块「下一步」直接引用，不重复展开。
- 落点：用户工程根下 `handoff-<主题>-<日期>.md`，或按接手方要求。**先输出全文给用户过目，确认后才写盘**。
- 接手侧：新会话第一件事是读交接文档，再按其「下一步」行动；文档里标「未核实」的东西，不得当已证事实继续往上盖。
- 在 ZCode 里可与 `ReadSessionContext` 互补：那个工具能从旧会话捞上下文，但交接文档给的是**结论后的状态**，两者都齐最稳。
