# mc-waitwhat — 话没落地，换一层讲

一句话目标：让用户听懂刚才那句话——同一结论换「讲结果、少术语」的层再讲一遍，不是把话再说含糊。

## 第 1 步 · 定位没落地的句子

- 从上一轮回复里引用用户卡住的那句（原话照抄），先分清卡的是**词**还是**信息**：
  - 卡词 → 第 2 步逐词解释。
  - 卡信息（缺背景）→ 明说「这句默认了 X」，补背景，别绕比喻。

## 第 2 步 · 按术语表对照重写

- 用户工程有 GLOSSARY.md（mc-glossary 产物）→ 拿表把每个承重词换成表内定义；没有表 → 首次出现的术语逐个先解释再用。
- 重写只换措辞，语义等同：结论、条件、数字、风险一个都不能变——变了的就不是重讲，是改口，改口要明说。
- 形状：先一句「我的意思是…」，再短段落展开；比喻最多一个，比喻之后回到字面。

## 第 3 步 · 自查

- 用「用户只能看到这段文字」重读：还有没有需要查上下文才懂的指代、自造简写、文件名黑话？有 → 再降一层。
- 重讲过程发现原结论站不住 → **停**，明说哪里站不住，回去查证或走 mc-research，禁止用更含糊的说法糊过去。

## 边界

- 同一个词第二次绊住用户 → 建议进 mc-glossary 立词条（立不立用户拍板）。
- 本技能只处理「话没落地」：不会操作 → mc-wizard；决定有分歧 → mc-grill；对事实存疑 → mc-research。
- 重讲不写盘；要沉淀的是词条，走 mc-glossary 的落盘规矩。
