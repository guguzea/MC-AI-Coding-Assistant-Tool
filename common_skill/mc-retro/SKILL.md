# mc-retro — 会话复盘

一句话目标：把这轮踩到的摩擦变成「下一条就能做的最小改进」，**只认本轮证据**。

## 找摩擦（按类各过一遍）

1. **导航** —— 哪一步因不知道文件 / 工具 / 模板名在哪而多花轮次？
2. **缺失的检查** —— 哪个错误若有条命令/门提前跑过就会被拦住？现在有没有这条命令？
3. **规则与措辞** —— agent 哪步没守某条规矩（是规矩有问题还是执行问题）？哪条规则把 agent 带偏了？
4. **可自动化的手工** —— 用户重复口述 / 手动执行了什么，其实有工具或能脚本化？

## 出建议（每条四件套）

- **现象**：本轮哪个位置发生的——引用到具体回合 / 文件 / 命令输出；给不出实例的猜测不进清单。
- **根因假设**：一句话，用可被推翻的写法（「可能是…」）。
- **最小改法**：具体到文件 / 命令 / 一句措辞；附「不做的代价」与「做了怎么验」。
- **排序**：下次还会踩的放最前，纯打磨放后。

## 边界

- 只复盘本轮：不搬记忆里的旧数与旧账凑数；本轮没摩擦就写「无改进项」，禁止硬造。
- **建议是清单不是授权**：改环境、改规则、加门都要用户点头；落在仓库受管面的改动另走维护流程，不在复盘里顺手做。
- 模组工程复盘与仓库维护复盘素材分两类，分节列。
