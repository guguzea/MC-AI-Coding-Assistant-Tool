# mc-wizard — 把「只能人做的」铺成人能照跑的

一句话目标：人在环的代价是人要动手；本技能把动手段变成不用动脑、照抄就行、每步知道自己是否做对了的向导。

## 第 0 步 · 分清哪些步骤必须是人做

典型清单（模组开发链）：

- 接受 EULA（改 `eula.txt`）——agent 永不代表用户接受。
- 游玩自测通道 B 授权：给出实例路径并确认（授权记录 = 原文 + realpath + 时间戳，由人给，不由 agent 自批）。
- 往未授权目录拷 jar、给正式实例装 mod——agent 只能教人做，不能代做。
- 重载宿主 MCP、IDE 设置、Modrinth / CurseForge 网页侧上传。
- 系统面（证书库、防火墙、hosts、代理）：永久禁止 agent 触碰——**向导里也不给一键命令**，只写「这是高危操作，你自己确认要做再动」。

不是人专属的步骤（写码、跑生成器、查文档）→ agent 自己走，不产出向导。

## 第 1 步 · 写向导的规则

- 每步**五件套**：做什么（一句）/ 在哪（具体路径或界面入口）/ 可粘贴命令（按用户系统给 PowerShell 或 CMD，空格路径加引号、`-encoding UTF-8` 这类已知坑就地注明）/ **判绿点**（文件在场、日志哪一行、界面什么状态——不许写「应该好了」）/ 失败长什么样、回哪一步。
- 占位符纪律：机器实况没在本会话实测过的路径、账号、版本号一律 `<在此填>`，禁止编。实测过的写实况并注明出处（哪条命令的输出）。
- 命令安全：向导里的命令不得含 agent 自己就被禁的动作（递归删用户数据、改网络栈、动正式实例）。高风险步骤（删 / 覆盖存档）前必须加「先备份：<路径>」。

## 第 2 步 · 交付与回链

- 全文先输出给用户过目；确认后落盘（默认 `docs/wizard-<主题>.md`）。
- 向导是**交互的**：用户做完一步、报判绿点，再继续讲下一步——不甩一篇长文让人盲跑。
- 跑完回到主链：人做完的那段，agent 从对应判绿点继续验证（例：桥装好 → `playtest_bridge` status 判 ready 再继续）。

## 边界

- 向导 = 人工步骤的生成器，不是授权申请器：遇「agent 本来不能做」的动作，写法是「由你亲手执行 + 判绿点」，不劝用户开自动化口子。
- 发布类步骤对齐 mc-publish 工作流的口径，不另造一套上传说明。
- 仓库维护侧的写盘操作不走本技能，走维护流程。
