# common_skill — 编排型技能源稿

这个文件夹放**跨平台、跨版本、纯流程**的编排技能源稿（需求对齐、会话交接这类"怎么问、怎么收尾"的程序），与平台树里的开发知识技能无关。

**待遇（2026-10-09 用户拍板）**：按普通文档放养——不进 AGENTS.md 受管名单，不配镜像门，改动不走维护档汇报。将来若出现源稿与安装件漂移事故或数量扩张，再议收编。

## 清单

| 技能 | 干什么 | 触发 |
| --- | --- | --- |
| `mc-grill` | 模组需求拷问：动手前把设计树每条分支问到用户拍板 | 新内容/新机制且需求未定型；或说「拷问我 / 帮我理需求 / grill」 |
| `mc-handoff` | 会话交接：把长会话实况压成六块交接文档，供新会话从中断处继续 | 换上下文/换机器/换宿主前；或说「交接 / 写个交接文档」 |
| `mc-router` | 流程路由：不确定走哪条流程时，按实况名单推荐主路线+备选+可直接执行的入口 | 问「该用什么 / 哪条流程 / 从哪开始」；情况已明确时不激活 |
| `mc-review` | 双轴评审：标准轴按该档规则/反模式核，规格轴对 spec/共识清单核对；用户点名时可切全仓体检模式；只出报告不代改 | 「review 这段改动 / 合并前把关 / 全项目体检」；报错走分诊不走这里 |
| `mc-spec` | 对话凝成规格：只综合本轮已拍板的，产出六节可验收文档 | grill 共识后；或「写成文档 / 定规格」 |
| `mc-breakdown` | 任务拆解：把 spec 拆成竖切片串（每片依赖 + 最低验收层级 L0–L7 + 对应开发模板），首片曳光弹穿骨架；多会话时该文档就是共享地图（待决栏 + 阻塞标记） | spec/共识已定；或「拆一下 / 先做哪个 / 怎么排任务」 |
| `mc-glossary` | 项目共同语言：为用户工程维护 GLOSSARY.md 与 ADR，spec/review/handoff 按同一套词对齐 | 「立术语表 / 记这个决定 / 统一命名」；或术语打架、决定重议时 |
| `mc-waitwhat` | 没听懂就重讲：引用原句、按术语表对照，同一结论换「讲结果少术语」层再讲一遍；只换措辞不改结论 | 「没看懂 / 什么意思 / 再说一遍」；不会操作走 wizard、分歧走 grill |
| `mc-research` | 带出处的调查：存在性/版本/坐标类事实题，来源分级 + 逐条出处 + 未核实点名 | 「X 存不存在 / 上游到第几 build / 这坐标对不对」 |
| `mc-prototype` | 一次性设计原型：GUI/HUD/tooltip 这类屏幕可见设计题做 2–3 个差异明显的单文件 HTML 变体给用户当场选，选完即弃 | 「给我看看几种方案 / 画个样子我选」；游戏内渲染与可行性不走这里 |
| `mc-wizard` | 人工步骤向导：把「只有人能做的操作」打包成可粘贴命令 + 逐步判绿点的向导文档 | 「接下来我该做什么 / 这些手动步骤怎么做」；EULA/授权/装桥/重载 MCP 场景 |
| `mc-retro` | 会话复盘：四类摩擦找点，建议带本轮证据与最小改法 | 收尾时；或「复盘 / 这轮哪里不顺」 |

**MCP 面入口（跨宿主，2026-10-09 已接）**：本目录的源稿同时经两个既有工具可达——

- `get_workflow_template --name=mc-grill` / `mc-handoff` / `mc-router` / `mc-review` / `mc-spec` / `mc-retro` / `mc-breakdown` / `mc-wizard` / `mc-research` / `mc-glossary` / `mc-waitwhat` / `mc-prototype`：编排清单（步骤 + 指向下面的正文 URI）
- `read_knowledge_resource --uri=mcskill://skill/<名字>`：读回本目录正文，实名单以 `list_knowledge_resources` 的 `skill-` 前缀条目为准（登记由盘派生，新增本目录技能自动出现）

对应源码面：`mcp-server/src/prompts/templates.ts`（模板体）、`src/prompts/index.ts`（`mcskill://skill/` URI 族）、`src/wave/register.ts`（工具 schema enum）、`src/platform-pack/session.ts`（TASK_SPECS 登记，test-platform-pack 要求每个模板名必须是已知 task）。改源稿后需 `npm run build` 并重载宿主 MCP。

## 派发纪律（编排技能派子任务时）

形状取自对 sandcastle 评审-合并接力的细读（2026-10-10，判据与来源见 mcp-server/CHANGELOG.md 第八十二批），三条都是编排侧的硬要求：

1. **事实预采随任务书走**：派发前编排者先用工具把实况采齐（平台与版本判定、文档命中页、涉及文件与行号、命令输出摘录）写进任务书；任务书里没有的事实，子代理一律标「未核实」，禁止凭训练记忆自研——子代理报错的根因与位置，多数源于让它自己找事实。
2. **机读输出用两遍式**：产出要进程序校验的任务，任务书固定尾段形状——正文自由写，末尾附一个只含 JSON 的标记块；编排侧按约定 schema 校验，失败时把校验错误原样喂回、只重派「提取」腿（重提取不重做工作腿）；一次重试仍不过的按「未核实」处理，不得静默接受坏形状。
3. **零产出短路**：对象没有变化就不重派校验者，直接引用上一轮证据并附轮次号与锚点路径；引不到轮次时按未验证处理。

## 安装与更新（本机，ZCode）

ZCode 用户级技能目录是 `~/.agents/skills/`，装进去后**任何项目的会话**都能用（新会话生效）。改完源稿跑一遍拷贝即可刷新：

```bat
copy /Y "common_skill\mc-grill\SKILL.md" "%USERPROFILE%\.agents\skills\mc-grill\SKILL.md"
```

纪律只有一条：**先改源稿，再拷贝刷新**；本机安装件永远是源稿的副本，出现不一致以源稿为准重新拷贝。
